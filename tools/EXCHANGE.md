# Регламент обмена данными: 1С ↔ сайт ↔ поставщик

Документ для сотрудника магазина. Всё построено так, что **доработки 1С не
требуются** — используются стандартные выгрузки.

---

## 1. Магазин: остатки из 1С → сайт

### Что делает сотрудник (2 минуты)

1. В 1С открыть: **Расчёты → Остатки и доступность товаров**
   (та же обработка, которой сделана выгрузка «Остатки и доступность
   товара.xlsx»).
2. Выгрузить в xlsx (кнопка «Сохранить/Выгрузить» — формат как в примере
   `tools/1c-stock-sample.xlsx`).
3. Положить файл в папку `tools/` (или любую — путь передаётся аргументом).

### Что делает скрипт

```bash
python3 tools/convert_1c.py "Остатки и доступность товара.xlsx"
# → data/shop-stock.json — виртуальный склад магазина
```

- позиции с отрицательным «Доступно» (предзаказы/дефицит) на витрину
  **не попадают**;
- розничная цена: известные артикулы rossimvol — опт ×2; остальное —
  прайс-модель по размеру; **если в выгрузке появится колонка «Цена»,
  скрипт подхватит её автоматически** (сейчас в формате 1С цен нет);
- артикулы нормализуются (в 1С они набраны смесью кириллицы/латиницы —
  «ММС»/«MMC»), чтобы совпадать с фото и номенклатурой поставщика.

### Периодичность

Хоть после каждой выгрузки из 1С — сайт просто перечитывает JSON.
Рекомендация: раз в день утром + после крупных продаж.

## 2. Удалённый склад: парсинг rossimvol.ru

```bash
# кубки и грамоты (умолчание)
python3 tools/parse_rossimvol.py

# свои разделы и лимит страниц
python3 tools/parse_rossimvol.py --cats cups,diplomas,medals,figuras --max-pages 10

# только JSON, без скачивания фото
python3 tools/parse_rossimvol.py --no-images
```

- обходит страницы категорий (`?PAGEN_1=N`), заходит в карточки и берёт
  **schema.org-микроразметку**: название, оптовая цена, наличие (InStock),
  фото (максимальное доступное качество `resize1`);
- позиции «нет в наличии» у поставщика в JSON не попадают — **купленное
  поставщиком товар не остаётся на витрине дольше одного цикла обновления**;
- цена на витрине = публичная цена поставщика («рекомендованная розничная»);
- **вариации группируются** в одну карточку (золото/серебро/бронза у медалей,
  размеры у кубков) — как у поставщика;
- **неполный модельный ряд бракует артикул целиком** (нет серебра — не
  публикуем весь артикул), остаток модели < 3 — тоже.

### Периодичность (настройка «частоты обновления»)

Пример cron на сервере/VPS:

```cron
# каталог поставщика — каждые 6 часов
0 */6 * * *  cd /srv/nagrada-mvp && python3 tools/parse_rossimvol.py >> logs/parse.log 2>&1

# магазин — конвертация свежей выгрузки 1С в 7:40 (файл кладётся заранее)
40 7 * * *   cd /srv/nagrada-mvp && python3 tools/convert_1c.py >> logs/1c.log 2>&1
```

Частота подбирается по торговле: часы пик → каждые 3 часа; спокойные
недели → раз в сутки. Меняется только расписанием cron, код не трогаем.

## 3. Заказы: сайт → сотрудник → 1С

Сейчас (демо): спецификация заказа (товар × количество, источник склада,
доставка, оплата, покупатель) выводится в оформленной форме на экране
успеха и в консоль браузера (JSON) — готовый документ для заведения в 1С.

Следующий шаг (бэкенд): та же спецификация уходит письмом/в MAX/в CRM
сотруднику. Формат уже финальный:

```json
{
  "num": "Р-1020", "date": "30.10.2026, 12:34:56",
  "buyer": { "name": "…", "phone": "…", "comment": "…" },
  "delivery": "Доставка курьером по городу", "pay": "Счёт для юр. лица",
  "items": [ { "name": "…", "art": "D-40", "src": "Магазин", "qty": 30, "price": 140, "sum": 4200 } ],
  "total": 4600
}
```

## 4. Требования к окружению

- Python 3.10+; единственная зависимость `openpyxl` (только для конвертера
  1С): `pip install openpyxl`;
- доступ к rossimvol.ru с машины запуска (защита ddos-guard пропускает
  обычные браузерные запросы, скрипт их имитирует);
- фото поставщика складываются в `img/remote/` (~37 МБ на 442 позиции —
  нормально для статического хостинга).
